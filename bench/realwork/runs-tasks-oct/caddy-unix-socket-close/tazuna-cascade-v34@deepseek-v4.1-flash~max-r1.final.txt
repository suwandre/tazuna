## Root cause

`unixListener.Close()`/`unixConn.Close()` derived the socket path from `uln.File().Name()`. In current Go, the file returned by `(*net.UnixListener).File()` is named by the netFD's display name (`unix:/path->`), not the filesystem path, so `syscall.Unlink` silently failed. Worse, that `*os.File` duplicate was never closed, so a dup of the listening fd stayed open and the socket kept accepting/pending connections until the runtime's finalizer closed the dup at the next GC — exactly the observed 2‑minute/GOGC=off behavior. There was also no idempotency guard, so a second `Close` decremented the shared reference count again, and abstract sockets could have a same-named filesystem path unlinked.

## Changes

`listen_unix.go`:
- `reuseUnixSocket` now closes the dup'ed `socketFile` (`defer socketFile.Close()`) and skips the pre-listen unlink for Linux abstract sockets (`@name`) via a new `isAbstractUnixSocket` helper.
- `unixListener`/`unixConn` gained a `closed atomic.Bool`; `Close()` CASes it, returns `net.ErrClosed` on a repeat call, and only decrements the shared reference count once.
- `Close()` now captures the path from `Addr()`/`LocalAddr()`, holds `unixSocketsMu` for the whole close (serializing with `NetworkAddress.Listen`, which already holds that mutex), closes the fd, and only deletes the map entry and unlinks the file when the count reaches zero and the address isn't abstract.
- Struct literals were updated for the new field.

`listen_unix_test.go` (new): covers immediate close+unlink, `unix`/`unixgram`, reference-counted reuse (file only removed at zero), double-close returning `net.ErrClosed` without releasing another reference, close/relisten races, and abstract-socket path protection (Linux-only skip elsewhere).

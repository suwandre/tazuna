## What was failing

The verifier runs from a checkout path containing a colon (`...@deepseek-v4.1-flash:max-cdjzo386`). `TestSnmpInitGosmi` panicked because gosmi's `AppendPath()` passes paths through `smi.SetPath()`, which splits on the OS path-list separator (`:` on Unix). With the colon in the checkout path, every MIB path was discarded, every module load failed, and the resulting `log.Warnf` call on the test's nil logger segfaulted. I confirmed the test passes from a colon-free symlinked path, and that the base commit fails identically.

## Fix for the test failure

`plugins/common/snmp/mib_loader.go`:
- Added a small `mibDirFS` (`fs.ReadDirFS`) that opens/reads a directory verbatim, and `GosmiMibLoader.appendPath` now registers it via `gosmi.AppendFS(gosmi.NamedFS(...))` instead of `gosmi.AppendPath(...)`, so gosmi never re-parses the path string (also works for directories containing `:` on Linux/macOS). Non-directory paths are skipped, matching the old validation behavior.
- `plugins/common/snmp/mib_loader_test.go`: added `TestMibDirFS`, covering Open/ReadDir on a directory whose name contains `:`.

The SNMP reconnect fix from before is unchanged: `Connection.Close`, `Reconnect` resetting SNMPv3 engine state only when closed, `Get`/`Walk` reconnecting first, and `inputs.snmp` closing the cached agent connection after any failed gather.

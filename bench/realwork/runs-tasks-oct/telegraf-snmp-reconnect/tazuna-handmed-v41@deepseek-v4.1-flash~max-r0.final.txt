**The earlier fix itself, which I kept:**
- `Close()` is added to the `snmp.Connection` interface.
- The input plugin closes an agent's cached connection whenever gathering its top-level fields or any table fails.
- In the common wrapper, `Get`/`Walk` reconnect first if the connection is closed.
- Reconnecting a closed connection clears the cached SNMPv3 engine ID, boots and time, so the next request runs a fresh engine discovery and resolves the agent address again.

I checked against the gosnmp source that this works:
- When the newly discovered engine ID differs from the cleared one, gosnmp drops and re-derives its cached keys.
- Reconnecting doesn't alter the configured transport.
- Closing an already-closed connection is harmless.

Fixed. `diff.mnemonicPrefix` (and `diff.noprefix` / custom `diff.srcPrefix`/`diff.dstPrefix`) no longer break hunk/line staging, discarding, or jump-to-file.

## What changed

**Path parsing** (`pkg/gui/controllers/helpers/diff_line_parser.go`)
- `pathFromDiffHeaderField` now unquotes first (`unquoteDiffPath`, extracted from the old inline logic) and then strips the path's first component, whatever it is (`a/`, `b/`, `i/`, `w/`, `c/`, ...) instead of only `a/`/`b/`. `/dev/null` is passed through, and a path with no `/` resolves to empty rather than a guess.
- `pathFromDiffHeader` now also reads the `rename to` / `copy to` line for sections without `---`/`+++` lines (pure renames/copies); mode-change and binary sections still fall back to the `diff --git` line.
- `pathFromDiffGitLine` no longer searches for `" b/"`: it splits the line at the space where both halves name the same path once their prefixes are stripped (like `git apply`), so paths containing spaces — or even ` w/` — work, quoted halves included. Differing halves (a rename) resolve to nothing and come from the rename/copy line instead.

**Command prefixes** (`pkg/commands/git_commands/git_command_builder.go` and call sites)
- New `GitCommandBuilder.ParseableDiffPrefixes()` forces `diff.noprefix=false`, `diff.srcPrefix=a/`, `diff.dstPrefix=b/` while deliberately leaving `diff.mnemonicPrefix` alone (its prefixes are single components too, so the user still sees `i/`/`w/`).
- Used everywhere lazygit asks git for a diff/`show`/`stash show` that it parses back (`diff.go`, `working_tree.go`, `commit.go`, `commit_file_loader.go`, `patch.go`, `stash.go`).

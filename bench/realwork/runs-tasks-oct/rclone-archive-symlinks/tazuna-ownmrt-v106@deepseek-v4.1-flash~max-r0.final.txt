## Summary

I added support for symbolic links in the archive backend (`zip` and `squashfs`), matching the convention the local backend uses for `-l`/`--links`.

### Behaviour

- **Without `--links`**: symlinks in an archive are skipped, and a single notice naming the flag is logged per `New` (zip) / per directory listing (squashfs).
- **With `--links`**: a symlink is listed under its own name plus the `.rclonelink` suffix, its `Size()` is the length of the target, and `Open` reads back the target path honouring `SeekOption`/`RangeOption`.
- **Listing and `NewObject` agree**: a link is only looked up under its suffixed name; the plain name returns `ErrorObjectNotFound`; and a regular member whose name ends in `.rclonelink` stays a regular file (`NewObject` tries the symlink interpretation first, then falls back to the literal name).
- A hostile archive (a symlink pointing above the destination plus a member "inside" it) is faithfully reproduced as a symlink by the local backend, but rclone's existing `os.Root` protection refuses the write-through, so nothing lands outside the destination (CWE-59).

### Files changed

- `backend/archive/zip/zip.go` — detect `os.ModeSymlink` entries, gate on `fs.GetConfig(ctx).Links`, append `fs.LinkSuffix`, count skipped links.
- `backend/archive/squashfs/squashfs.go` — expose symlinks via go-diskfs's `Readlink`, add `isLink`/`linkTarget` to `Object`, split `newObjectNative` into `findNative`/`findNativeObject`, and add `newStringReadCloser` for range/seek-aware target reads.

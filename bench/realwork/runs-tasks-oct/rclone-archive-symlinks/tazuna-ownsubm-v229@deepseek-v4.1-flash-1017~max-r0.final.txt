## What changed

**`backend/archive/zip/zip.go`**
- Added a `links` field populated from `fs.GetConfig(ctx).Links` (`-l/--links`).
- While reading the zip central directory, members whose mode has `os.ModeSymlink` are now:
  - skipped when `--links` is off, with a notice naming the flag (logged once per archive);
  - listed under `name + fs.LinkSuffix` when `--links` is on. The suffix is added *before* root matching, so a symlink can be addressed as a single object by its suffixed name.
- Symlink objects keep the zip entry as their content, so `Size()` is the target length and `Open()` naturally honours `SeekOption`/`RangeOption` (the existing offset/limit code applies).
- A regular member whose name already ends in `.rclonelink` is untouched — it stays a regular file.

**`backend/archive/squashfs/squashfs.go`**
- Same `links` option. Symlinks (previously dropped with a "FIXME Not regular file" debug) are now:
  - skipped with a flag-naming notice when `--links` is off;
  - exposed as `.rclonelink` objects whose `Size()` is the target length and whose `Open()` returns the target (honouring range/seek), using the go-diskfs `StatT.LinkTarget`.
- `newObjectNative` and `List` agree on names: an unsuffixed symlink name gives `ErrorObjectNotFound`, the suffixed one resolves only to a symlink, and a real regular file with the suffix wins as a regular file.
- Shared `openLink` helper mirrors the local backend's clamping behaviour for offsets past the end.

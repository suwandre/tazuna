## What changed

**`modules/caddyhttp/celmatcher.go`**
- `MatchExpression` now records the Caddy placeholder names its compiled CEL AST actually reads (`celPlaceholderNames` walks the AST and inspects each `ph(req, "...")` call, including ones written directly with `ph()`).
- Names that aren't string literals (e.g. `ph(req, "http.reverse_proxy." + "status_code")`) are recorded as `""`, meaning "unknown until evaluation".
- New `Placeholders()` accessor returns those names.

**`modules/caddyhttp/reverseproxy/reverseproxy.go`**
- Replaced `matcherSetHasExpressionMatcher` (which made *any* expression matcher response-based) with `matcherSetReferencesResponse`, which only treats a matcher set as a response condition when an expression actually reads response data:
  - `http.reverse_proxy.status_code` / `status_text`
  - `http.reverse_proxy.header.*` (prefix match, so real header placeholders work)
  - `http.reverse_proxy.upstream.latency` / `latency_ms`
  - or an unknown/dynamic placeholder name
- Request-only expressions (`{http.request.method}`, `{http.reverse_proxy.upstream.host}`, escaped `\{http.reverse_proxy.status_code}` inside a string literal, `{http.reverse_proxy.status_codes}`, etc.) are no longer evaluated against successful responses, so they behave as pre-v2.11.3 request conditions again.
- Updated the `LoadBalancing.RetryMatchRaw` doc comment accordingly.

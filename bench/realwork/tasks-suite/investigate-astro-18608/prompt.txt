### Describe the Bug

When `astro dev` starts without an existing `.astro/data-store.json` (a fresh clone, or after deleting `.astro/`), the first page opened loads and then immediately does a full reload. It happens once per start. A start with the data store already on disk does not reload. This is the same symptom as #17283, but it comes from a different call site than the one #17286 fixed, and it needs a project with a content collection.

**Observed**

In the linked reproduction (one glob-loader collection with one entry, one page that calls `getCollection`), after a fresh start the first page shows `page load #2`. The browser's HMR websocket receives:

```text
{"type":"connected"}
{"type":"full-reload","path":"*"}
{"type":"connected"}
```

Restarting with `.astro/` left in place gives `page load #1` and only `{"type":"connected"}`. I checked both cases repeatedly on the same port. Both behave the same every time.

To find the sender, I temporarily added a log just before the `full-reload` send in `invalidateDataStore` in `node_modules`. On a fresh start it fired exactly once, with `viteServer.ws.clients.size === 0`, and this stack:

```text
at invalidateDataStore (astro/dist/content/vite-plugin-content-virtual-mod.js)
at <store.onFileWritten listener> (astro/dist/content/vite-plugin-content-virtual-mod.js)
at #notifyFileWritten (astro/dist/content/mutable-data-store.js)
at MutableDataStore.writeToDisk (astro/dist/content/mutable-data-store.js)
at async #saveToDiskNow (astro/dist/content/mutable-data-store.js)
at async MutableDataStore.waitUntilSaveComplete (astro/dist/content/mutable-data-store.js)
at async #doSync (astro/dist/content/content-layer.js)
```

With that listener's call changed to `invalidateDataStore(server, { notifyClient: false })`, a fresh start no longer reloads the first page.

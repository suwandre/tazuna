A bug report came in for this repository:

Title: Nested class attribute docstrings overwrite outer field descriptions

### Initial Checks

- [x] I confirm that I'm using Pydantic V2

### Description

With use_attribute_docstrings=True, a nested class’s field docstring overwrites the outer class’s field description when both fields have the same name.

Defining the classes at module level produces the correct descriptions.

### Example Code

```Python
import json

from pydantic import BaseModel, ConfigDict


class Outer(BaseModel):
    model_config = ConfigDict(use_attribute_docstrings=True)

    x: int
    """Outer field."""

    inner: Inner

class Inner(BaseModel):
    model_config = ConfigDict(use_attribute_docstrings=True)

    x: str
    """Inner field."""


class OuterWrong(BaseModel):
    model_config = ConfigDict(use_attribute_docstrings=True)

    x: int
    """Outer field."""

    inner: InnerWrong

    class InnerWrong(BaseModel):
        model_config = ConfigDict(use_attribute_docstrings=True)

        x: str
        """Inner field."""



print("CORRECT:\n", json.dumps(Outer.model_json_schema(), indent=2))
print("WRONG - outer field x has the inner field's description:\n", json.dumps(OuterWrong.model_json_schema(), indent=2))
```

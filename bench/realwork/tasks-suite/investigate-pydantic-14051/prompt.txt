A bug report came in for this repository:

Title: KeyError when unpickling (some) ValidationErrors

### Initial Checks

- [x] I confirm that I'm using Pydantic V2

### Description

After https://github.com/pydantic/pydantic-core/pull/1119 some ValidationErrors are picklable but there are a few types that raise a KeyError. The example below is from a builtin error but anything created as a `PydanticCustomError` also fails in the same way with whatever is passed in as the `error_type` being raised in the `KeyError`.

### Example Code

```Python
from pydantic import BaseModel, ValidationError
from collections.abc import Sequence
import pickle

class Foo(BaseModel):
    bar: Sequence[str]

try:
    f = Foo(bar="buzz")
except ValidationError as e:
    pickle.loads(pickle.dumps(e))
```

Gives

```
pydantic_core._pydantic_core.ValidationError: 1 validation error for Foo
bar
  'str' instances are not allowed as a Sequence value [type=sequence_str, input_value='buzz', input_type=str]

During handling of the above exception, another exception occurred:

Traceback (most recent call last):
  File "<stdin>", line 11, in <module>
KeyError: "Invalid error type: 'sequence_str'"
```

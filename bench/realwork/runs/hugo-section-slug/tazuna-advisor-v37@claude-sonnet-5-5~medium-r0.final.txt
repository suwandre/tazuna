Setting `slug` in the front matter of a section, taxonomy or term page now changes its URL and the URLs of everything under it. Your `help/` example produces `es/ayuda/` and `es/ayuda/como-frobear/`. The new test passes, and `go test ./hugolib/... ./resources/...` passes. I did not run `./check.sh`.

- **How it works:** `hugolib/page__paths.go` has a new function, `sectionBaseWithSlugs`, that rebuilds the section path from the root down. Each section contributes its `slug` if it has one, otherwise its directory name. `resources/page/page_paths.go` uses that path for branch pages and for the section part of a page's directory. It stays empty when no section in the chain has a slug, so existing sites are unaffected.
- **Test:** `TestSectionSlug` in `hugolib/section_slug_test.go` covers your example with an English and a Spanish language. It also checks a nested section (`es/ayuda/sub-es/`) and a taxonomy (`es/etiquetas/`). The term case checked is `es/etiquetas/t1/`, which gets the slug only from its taxonomy. I did not test a slug set on a term page itself.
- **Config route:** the existing `permalinks` config with `:sectionslugs` still works, and a `url` set in front matter still takes precedence over a slug.

Fixed: a quoted `"{"` or `"}"` (in double quotes, backticks or a heredoc) is now read as a plain string, not as the start or end of a block. The example from the issue now adapts to a `static_response` with body `{`.

**The cause.** The parser and the `Dispenser` decided whether a token was a brace by checking only its text (`Val() == "{"`). They never looked at whether it had been quoted. Two things went wrong as a result:
- The parser counted `"{"` as opening a new block level, which threw off its brace counting.
- `Dispenser.NextArg()` treated `"{"` as the start of a block and stepped back over it, so `respond` thought it had no argument. That's where the "wrong argument count" error came from.

**The fix** (all in `caddyconfig/caddyfile/`):
- `lexer.go`: two new helpers on `Token`, `isOpenBrace()` and `isCloseBrace()`, which only match a brace that wasn't quoted.
- `dispenser.go`: `NextArg`, `NextBlock` and `ArgErr` now use the helpers.
- `parse.go`: every brace check uses the helpers too. That covers site addresses, `directives`, `directive`, `openCurlyBrace`/`closeCurlyBrace`, `blockTokens`, the brace counting for snippets and import blocks, and the anonymous-import-block check. In `directive()`, an old check for whether the brace was quoted is no longer needed, so I removed it.

I searched the rest of the repo and found no other code that tests for braces by text, so the change stays inside this one package.

**Tests added:**
- `TestQuotedBracesAreNotBlockDelimiters` in `parse_test.go`. It covers quoted braces in double quotes and backticks, inside nested blocks and inside snippets. It also checks that `"{"` can't open a server block and that `"}"` can't close one.
- `TestDispenser_QuotedBraces` in `dispenser_test.go`, for quoted braces as arguments and inside blocks.
- An end-to-end adapt test, `caddytest/integration/caddyfile_adapt/quoted_braces.caddyfiletest`, using `"{"`, `` `}` `` and `"{}"`.

`go test -race -short` passes for `./caddyconfig/...` and `./modules/caddyhttp/...`, and the Caddyfile adapt integration tests pass. `go vet` and `gofmt` are clean. I didn't run `golangci-lint`.

**Two things I left alone:**
- If the server block's final closing `}` is missing at the end of the file, the parser silently accepts it. That was already true before this change; I adjusted one test case so it doesn't depend on that.
- A quoted site address ending in `{` (like `"foo{"`) still gets the "put a space before the brace" error. The address would be invalid anyway.

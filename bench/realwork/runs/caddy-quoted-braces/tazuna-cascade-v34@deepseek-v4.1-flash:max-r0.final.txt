## Summary

Quoted/backtick/heredoc `{` and `}` tokens are no longer treated as structural block delimiters; they are now ordinary arguments, so:

```caddyfile
:8080 {
	respond "{"
}
```

adapts correctly instead of failing.

### Changes

- **`caddyconfig/caddyfile/lexer.go`** — added `isOpenCurlyBrace(Token)` / `isCloseCurlyBrace(Token)` helpers which require the token to be unquoted (`wasQuoted == 0`).
- **`caddyconfig/caddyfile/dispenser.go`** — `NextArg`, `NextBlock`, and `ArgErr` now use the helpers, so a quoted `"{"` is returned as an argument rather than ending args/opening a block, and quoted `"}"` no longer closes one. Doc comments updated.
- **`caddyconfig/caddyfile/parse.go`** — all block-structure checks (`addresses`, `directives`, `doImport` snippet tracking, `directive`, `openCurlyBrace`, `closeCurlyBrace`, `blockTokens`) use the helpers. Also, the "site address ends with `{`" error and the `"{}"` at end-of-line error now skip quoted tokens.
- **Tests** — added `TestDispenser_QuotedBracesAreArguments`, table cases in `TestParseOneAndImport` (quoted braces as args, quoted `"{"` followed by a real block), `TestSnippetWithQuotedBraces`, a formatter preservation case, and the integration fixture `caddytest/integration/caddyfile_adapt/quoted_brace_args.caddyfiletest` covering the exact reported config plus quoted `}` headers.

**Cause.** The lexer already records whether a token was quoted (`wasQuoted`). The parser and dispenser ignored that and compared only the text, so `"{"` was counted as an open brace. That raised the nesting level and left the block unclosed.

**Fix.**
- **Helpers:** I added two unexported helpers, `Token.isOpenBrace()` and `Token.isCloseBrace()`, in `caddyconfig/caddyfile/lexer.go`. They match only unquoted braces.
- **`parse.go`:** `directive()`, `directives()`, `openCurlyBrace()`, `closeCurlyBrace()`, `blockTokens()` and the snippet/`{block}` token scan now use the helpers.
- **`dispenser.go`:** `NextArg()` and `NextBlock()` use them too. Directive modules therefore receive a quoted `"{"` or `"}"` as an ordinary argument instead of having it dropped.
- **Cleanup:** I removed the old `wasQuoted == 0` workaround in `directive()`. The new check makes it redundant.

**Tests.**
- **`parse_test.go`:** five new cases cover quoted `{` and `}` at the top level, inside a braced site block, and inside a nested block.
- **`dispenser_test.go`:** `TestDispenser_QuotedBracesAreArguments` covers `NextArg` and `NextBlock`.
- **Other checks:** `go build ./...`, `go vet ./caddyconfig/...` and `gofmt -l` were clean. I ran `caddy adapt` on the exact config from the issue.
- **Not checked:** I didn't confirm the new tests fail without the fix. `gopls` isn't installed, so I got no LSP diagnostics.

I left site-address parsing alone: a quoted `"{"` as a site address still goes through the existing address checks. This is a separate edge case from the one in the issue.

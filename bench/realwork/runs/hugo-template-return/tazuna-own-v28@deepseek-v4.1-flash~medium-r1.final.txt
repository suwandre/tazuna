I implemented the improved `return` keyword by replacing the partial return template rewriting with a sentinel error trapped in the template executor.

## Changes

**Executor fork** (`tpl/internal/go_templates/texttemplate/`):
- `hugo_template.go`: Added `ReturnError` sentinel. A bare `{{ return }}` (no value) is trapped at the nearest template boundary (`executeWithState` for the top level, `walkTemplate` for `{{ template }}` includes); `{{ return <value> }}` propagates as an error to be trapped by the partial invocation. `evalFunction` intercepts `return`, evaluates everything after it as a command (so `{{ return add . 42 }}` works), and panics with the sentinel. Also guarded the `try` recover so it doesn't swallow a `ReturnError`.
- `exec.go`: Renamed `walkTemplate` → `walkTemplateOld` (one mechanical rename), mirrored in `scripts/fork_go_templates/main.go`.

**Transform cleanup** (`tpl/tplimpl/`):
- Removed the `partialReturnWrapper` template, `wrapInPartialReturnWrapper`, `applyTransformationsAndSetReturnWrapper`, `collectReturnNode`, the `returnNode` field, and `ParseInfo.HasReturn`.
- `applyTransformations` now just recurses/validates; it rejects `return` in a non-final pipeline position (`return must be the last command in a pipeline`).

**Partials** (`tpl/partials/`):
- `doInclude` no longer uses a `contextWrapper` to capture the return value; it executes normally and uses `errors.As` to detect `*texttemplate.ReturnError`, discarding any rendered output and returning `rerr.Value`.
- `return` now maps to `func(v ...any) any` instead of the old placeholder.

**Behavior**: `return` works in any template (not just partials), anywhere/any number of times, following normal flow control. `{{ return <value> }}` outside a partial is now an error instead of being silently ignored.

**Docs & tests**: Updated `docs/content/en/functions/go-template/return.md`, added integration tests in `hugolib/template_test.go` and `tpl/partials/partials_integration_test.go`, and updated the `tpl/templates` panic test expectation.

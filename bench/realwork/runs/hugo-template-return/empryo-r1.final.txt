- **Mechanism.** The `return` func (`tpl/partials/init.go`) returns a `*texttemplate.ReturnError{Value}` sentinel. `evalCall` in `texttemplate/hugo_template.go` panics with it, and `errRecover` in `texttemplate/exec.go` turns it into the execution's error. The fork changes are small: the `ReturnError` type, a few lines in `evalCall`, `evalFunction` and `errRecover`, plus a re-panic in the `try` recover. `try` doesn't swallow `return`.
- **Store.** `TemplateStore.ExecuteWithContext` treats the sentinel as a normal exit. `ExecuteWithContextAndKey` hands it back unwrapped.
- **Partials.** `doInclude` in `tpl/partials/partials.go` catches it and uses `Value` as the result, discarding any output so far. The `contextWrapper`, `HasReturn` and the whole `partialReturnWrapper` rewrite in `templatetransform.go` are gone, so `.` and `$` are no longer rebound.
- **Shorthand.** `{{ return add . 42 }}` still works, so existing partials are unaffected. It is handled in `evalFunction` and means `return (add . 42)`.
- **Decorator else branch.** When a `with partial` block's partial doesn't call `inner`, the block body is copied into an else branch and runs in place. A `return` there would have ended the enclosing template, so `neutralizeReturn` swaps it for a no-op `_returnNoop`. This is the one remaining AST rewrite.
- **Bare return.** `{{ return }}` in a partial returns nil, as in your sketch, not the output rendered so far.
- **Nested templates.** A `return` inside `{{ template "x" }}` or a nested `define` ends the whole execution, not just that template.
- **Test changes.** New tests in `tpl/partials/partials_integration_test.go` cover early return in a regular template, in a partial and inside a `range`, bare return, piped `| return`, and a decorator block that doesn't call `inner`.

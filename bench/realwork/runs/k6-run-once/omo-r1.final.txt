**Behavior**
- **Where it runs:** the transform runs in `consolidateDeriveAndValidateConfig` right after `getConsolidatedConfig`, so `k6 run`, `cloud run` (including `--local-execution`) and `archive` all get it. `inspect` and `cloud upload` don't define the flag, so they are untouched.
- **No scenarios:** the script gets a `default` shared-iterations scenario with 1 VU and 1 iteration. Any script-level `vus`, `iterations`, `duration` or `stages` are dropped.
- **Single scenario:** it becomes shared-iterations with 1 VU and 1 iteration. It keeps its name, `exec`, `env`, `tags` and browser `options`, and drops `startTime`, `gracefulStop` and the old executor fields.
- **Multiple scenarios:** the run fails with `--once can run a single scenario only, but the script defines N: a, b`.
- **Shortcut flags:** `--once` with `--vus`, `--iterations`, `--duration` or `--stage` fails with `--once cannot be combined with --X`.
- **Exit code:** both errors exit with the invalid-config code.
- **Archive and cloud:** both only use the consolidated config. Because the transform runs before derivation, the archive and cloud upload contain the 1/1 scenario.

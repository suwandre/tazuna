The fix matches the plan and solves the reported bug: every import block is now kept, not just the first one per `for_each` resource. A parent module's import block still overrides a child's for the same resource.

**The fix:** `FindImportStatements` in `internal/refactoring/import_statement.go` used to key import blocks by resource and skip any later block for a resource it had already seen. That's why `t["b"]` was silently dropped and planned for creation. It now keeps every block and only skips blocks from a child module when a parent module already imports that resource. `findImportTargets` in `internal/terraform/context_plan.go` was updated to read the new list.

That didn't affect what the tests check, since the import ID comes from the import block, but the fake didn't match its schema. I replaced it with the same fixed response the existing `TestContext2Plan_importForEach` uses. I also staged the edited test file alongside the implementer's staged changes.

I've added the `tls_automate_names` global option. In your example, the `tls` app now comes out with exactly the same automation policies as the dummy `*.example.com {}` version. The two differences are that the extra route is gone and the name is listed under `certificates.automate`.

**Changes**
- **`caddyconfig/httpcaddyfile/options.go`**: registers the option. It needs at least one name, repeating it adds to the list, and duplicate names are dropped.
- **`caddyconfig/httpcaddyfile/tlsapp.go`**: in `buildTLSApp`, every listed name goes into the `automate` loader. Each name also gets the automation policy a site block would give it, built from the same global options, unless a site block already provides one. So:
  - **No site blocks:** only the `tls` app is produced, with no `http` app.
  - **`localhost` and IP addresses** get an automation policy that uses the internal issuer. A site block doesn't need this, because the `http` app assigns the internal issuer itself, but with no route nothing else would do it. If `local_certs` or `cert_issuer` is set globally, that issuer is used for all the names, the same as for site blocks.
  - **Name that also has an HTTPS site block:** it stays in the list, the site block's policy is used, and no second policy is added.
  - **Name whose site block is `http://` only:** it gets its own policy and certificate.
  - **`auto_https off`:** the names are still listed for automation.
  - **Invalid names** (ones that can't get any certificate) cause an adapt error.

**Testing**
- I ran `caddy adapt` on the "with option" and "dummy site block" versions under `email`, `local_certs`, `key_type`, `acme_ca` and no options. The policies matched in every case; the only difference was the `automate` entry.
- I added four adapter test files in `caddytest/integration/caddyfile_adapt/`: the basic case, no site blocks with mixed public and internal names, overlap with an HTTPS site block and an `http://` site, and `auto_https off`. Their expected JSON was generated by the new code, and I checked it by hand.
- I added `TestGlobalTLSAutomateNamesOption` in `options_test.go`. It covers adding names across repeats, dropping duplicates, and the error when no names are given.

**Known gap:** Tailscale `*.ts.net` names in this list would get an ACME policy. A site block gets a Tailscale certificate manager from the `http` app, and I didn't copy that.

How each requirement is met:
- **Repeating the option:** each `tls_automate_names` line adds to the list. Names are lowercased and duplicates removed.
- **Certificates without routes:** the names go into `certificates.automate` and never get a route. With no site blocks, only the `tls` app is produced.
- **Global options like `email`:** for the issue's example, the automation policies are byte-for-byte the same as with the dummy `*.example.com {}` site block. Only the extra route is gone.
- **`localhost` and IP addresses:** they get an explicit `internal` issuer policy. This has to be explicit because there may be no HTTP app to assign that issuer at runtime.
- **Names that also have a site block:** they stay in the automate list, and only the site block's policy is used, so there's no second, conflicting one. A name whose site block is `http://`-only gets its own policy, so it still gets a certificate.
- **`auto_https off`:** the names are still listed for automation.

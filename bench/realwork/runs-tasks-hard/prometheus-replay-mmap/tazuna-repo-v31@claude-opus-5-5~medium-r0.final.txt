**The fix** (`tsdb/head_wal.go`, `resetSeriesWithMMappedChunks`): when a second WAL reference resolves to the same live series, its mapped chunks are now merged in rather than replacing the series' existing ones.
- **OOO chunks** from both references are kept.
- **In-order chunks:** existing chunks that end at or before the new reference's last chunk are dropped as already-compacted history, and the later ones are kept. If the new reference has no chunks, nothing is dropped.
- **Unchanged:** the replayed in-memory samples are still reset. When the reference matches the live series, the old replace behaviour still applies.
- **Metrics:** the chunk counters now count only chunks that were actually added or dropped.

One limit: if the new reference has no mapped chunks, old in-order chunks of the earlier reference that weren't already skipped at load are kept, not dropped. In normal operation those are below the minimum valid time and skipped when loading.

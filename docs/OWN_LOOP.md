# Design: tazuna's own agent loop

Status: first slice built (0.0.28); the rest is design. Roadmap "Next" item 3.

## Why

Today tazuna wraps the `claude` CLI: the agent loop (ask the model, run the tools it asks for, send the results back, repeat)
runs inside `claude`. That rules out three things the goals need:

1. **Other providers.** `claude` drives only Claude models. Cheap implementers (GPT-6 Luna, MiMo 2.6 Pro, DeepSeek V4.1 Flash,
   local models) with a Claude reviewer need a loop tazuna owns.
2. **The footprint floor.** The `claude` process under tazuna is ~190 MB and ~0.5 s to start; tazuna's own part is 7 MB and
   6 ms. Only an own loop gets the total near tazuna's part.
3. **Full token control.** Exact prompt bytes, cache breakpoints, tool output trimming, effort and model per call, hand-off
   instead of compaction: the CLI decides most of these today.

**Not a goal:** Claude on the user's subscription. That stays on the `claude` CLI path (no impersonation, no reuse of its
login). The own loop uses API keys only (Claude through an Anthropic API key is possible, billed per token).

## Shape: a second engine behind the same events

Everything above the engine already works on claude's stream-json events: the session state, the UI, recordings and replay,
the run log, verification, the reviewer, permission questions, background-task handling. So the own loop **emits the same
events** claude does, into the same channel `Live` already reads, and accepts the same inputs:

| Direction | claude CLI today | Own loop |
|---|---|---|
| out | `system/init`, `stream_event` deltas, `assistant`, `user` (tool results), `result` with usage and cost | the same JSON shapes, generated by tazuna |
| out | `control_request` `can_use_tool` (permission question) | the same, so `ask`/`edits`/`plan` work unchanged |
| in | user message line on stdin | the same message, via a channel |
| in | `control_request` `interrupt` / `set_permission_mode` | handled by the loop |

`Live::spawn` picks the engine: the `claude` process, or a thread running the loop. `Live`, `Session`, the UI and the run log
do not change. This keeps the change to one new module plus a provider adapter, and every existing feature and test keeps
covering both engines.

## Parts

1. **Provider adapters** (`src/provider/`)
   - **OpenAI-compatible Chat Completions, streaming:** covers OpenAI, OpenRouter, DeepSeek, Xiaomi MiMo, and local servers
     (llama.cpp, vLLM, Ollama). One adapter, a base URL and a key per provider.
   - **Anthropic Messages, streaming:** API key only; `cache_control` breakpoints on the system prompt and the last tool result.
   - Each adapter turns tazuna's request (system, messages, tool schemas, effort) into the provider's format and the stream
     back into deltas, tool calls and usage.
2. **The loop** (`src/own.rs`): keep the conversation; per turn call the model, stream text and tool calls, run the tools,
   append the results, repeat until the model stops calling tools. Read-only tools run in parallel. Every loop has
   done / check / stop / budget (roadmap rules): a turn cap, a dollar cap per run, and a stop on interrupt.
3. **Tools:** reuse the lean tools in-process (`mcp.rs`: bash, read, write, edit, same descriptions and output cap) plus grep
   and glob. After any tool call that changed files, run the diagnostics check directly (today a claude hook).
4. **Prompt and cache:** the lean prompt plus the repo's `CLAUDE.md` / `AGENTS.md`, byte-stable across turns so automatic
   prefix caching (OpenAI, DeepSeek) and explicit breakpoints (Anthropic) hit every turn. Large tool output goes to disk with
   a pointer, as the bash cap already does.
5. **Cost:** a price table per model (input, cached input, output) in the provider config; the loop reports `total_cost_usd`
   like claude, so the run log, the Cockpit and the benchmarks need no change.
6. **Config:** `~/.config/tazuna/providers.toml`: provider name, base URL, the environment variable that holds the key,
   models with prices and context window. Keys are read from the environment only, never written to logs or recordings.
7. **HTTP:** a small blocking client (`ureq` with rustls) and a hand-written SSE reader; expected +1 MB of binary.

## First slice (2026-10-09)

Goal: one cheap model finishes one Go task headless through tazuna, with its cost in the run log, under a dollar cap.
Provider: CheaperInference (`https://api.cheaperinference.com/v1`, OpenAI-compatible, key in `CHEAPER_INFERENCE_API_KEY`),
a $15 prepaid test account.

**In:**
- **Engine as a process, not a thread:** `tazuna --engine` reads and writes stream-json on stdin/stdout like `claude -p`.
  `spawn()` starts it instead of `claude` when `--provider-url` is given. `Live`'s stdin/stdout plumbing, the run log,
  verification and the reviewer stay unchanged (the same pattern as `mcp::serve`). A thread can come later if the extra
  process (~7 MB) matters.
- **Chat Completions without streaming:** no SSE reader and no partial tool-call JSON yet. Per turn the engine emits
  `assistant` (text and `tool_use` blocks), then `user` (`tool_result`), and at the end `result` with usage,
  `total_cost_usd` and `num_turns`; `system/init` at start.
- **Tools:** `mcp.rs`'s `Server` in-process (bash, read, write, edit; same descriptions and output caps). Grep and glob
  wait; bash covers them.
- **Config by flags:** `--provider-url`, `--provider-key-env`, `--model`. Prices come from the provider's `/v1/models`
  (CheaperInference lists input, cached input and output per million tokens for every model); cached tokens from
  `usage.prompt_tokens_details.cached_tokens`. A `--price` override and `providers.toml` wait for a provider without prices.
- **Caps:** `--max-turns` (default 60) and `--max-usd` (default 0.50 per run) end the run with an error `result`.
- **Permission:** the `auto` mode only (headless). Interrupt: stop before the next model call.
- **Dependency:** `ureq` with rustls.
- **Test:** one offline test drives the loop with canned replies (a tool call, its result, a final answer) and checks the
  events and the cost. No mock server.

**Out (next slices):** streaming and live deltas in the UI, the other permission modes, the Anthropic adapter, prompt-cache
control, `providers.toml`, diagnostics after edits, hand-off instead of compaction.

**Candidates** (CheaperInference, USD per million tokens, input / cached / output): DeepSeek V4.1 Flash 0.15 / 0.003 /
0.60, GPT-6 Luna 0.065 / 0.006 / 0.325, MiMo V2.6 Pro 0.283 / 0.002 / 0.566. For scale: Opus 5.5 there 2.60 / 0.13 / 13.00.
Start with DeepSeek V4.1 Flash, then GPT-6 Luna.

**Check, one step at a time (each step waits for the user):** 1. DeepSeek V4.1 Flash on one Go task (smoke, ≤ $0.50),
report the spend. 2. The same model on the six Go tasks × 1 run (≤ $0.50 per run), judged by Opus on the subscription
against tazuna's default on Claude. 3. Only then a second model. Keep ≥ $5 of the $15 in reserve. Company tickets stay off
this provider (company code to a third party).

**Stop rule:** if the slice takes more than a day or grows past ~600 lines, stop and report instead of widening it.

## Later (after the minimum version)

- Hand-off instead of compaction near the context limit: a summary turn, then a fresh conversation (parked idea).
- Cross-provider pairs: a cheap implementer here with a Claude reviewer through `--review-model` (works already).
- Per-step models: a cheap model for exploration, a strong one for edits (the parked "heavy profile").

## Minimum version and test

- OpenAI-compatible streaming, the six tools, the `auto` permission mode first (then the others through the same
  `can_use_tool` events), interrupt, cost, the turn and dollar caps. About a day of work.
- **Tests without spending:** a local mock server that streams canned responses (text, tool calls, usage), so the loop,
  tool execution, interrupt and cost are tested offline.
- **Benchmark:** the six Go tasks with the shared judge, own loop + each candidate model against tazuna on Claude, with a
  per-run dollar cap. Real money, not subscription usage.

## Risks

- **Provider quirks:** tool-call streaming differs (partial JSON arguments, parallel calls, reasoning fields). Mitigation:
  start with one provider, test against recorded streams.
- **Quality of non-Claude models on agentic tasks** is the open question the benchmark answers; the engine is cheap to keep
  even if the first models disappoint.
- **Safety:** the same git-repo rule and permission modes apply; the loop must never put API keys into tool environments
  (the bash tool already strips tokens) or recordings.
